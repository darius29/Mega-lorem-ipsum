Mega Lorem Ipsum
A full-stack records management application built with React, Express.js, and SQLite.

The application provides a responsive, searchable, sortable table of records, with Create, Edit, and Delete operations handled through modal dialogs.

Tech Stack
Frontend React, Vite, JavaScript, SCSS (Sass), Lucide React
Backend Node.js, Express.js
Database SQLite (better-sqlite3)
Testing Node.js built-in test runner, Supertest

Features

- 200 sample records generated by the database seed script.
- Seven-column table: ID, Title, Category, Description, Status, Created At, and Actions.
- Live search across the visible record fields.
- Sortable columns in ascending and descending order.
- Pagination with 20 records per page.
- Create and Edit forms with required-field validation and inline error messages.
- Delete confirmation before an existing record is removed.
- Native <dialog> modals with animated opening and closing, Escape / X / outside-click dismissal, keyboard navigation, and focus restoration.
- Background scroll locking while a modal is open.
- Shareable modal URLs for Create, Edit, and Delete, with browser Back/Forward support.
- Responsive interface, with a horizontally scrollable table on narrower screens.
- Category and status badges, custom favicon, and keyboard focus styles.

Prerequisites

- Node.js and npm
- Git (to clone the repository)
  Getting Started
  Clone the repository:
  ```
  git clone https://github.com/darius29/Mega-lorem-ipsum.git
  cd Mega-lorem-ipsum
  ```

1. Set up the backend
   In your first terminal:
   ```
   cd server
   npm install
   npm run seed
   npm run dev
   ```
   The API runs at http://localhost:3001 by default.
   Important: Run npm run seed at least once on a fresh clone. The SQLite database file is intentionally excluded from Git, so an initial database will otherwise contain no sample records. The seed script inserts 200 records only when the records table is empty; it does not append another 200 records to a non-empty table.

3. Set up the frontend
   In a second terminal, starting from the repository root:
   ```
   cd client
   npm install
   npm run dev
   ```
   Open http://localhost:5173 in your browser.

Keep both the backend and frontend running while using the application.

REST API
```
Base URL: http://localhost:3001/api/records
Method Endpoint Description Success response
GET /api/records Get all records 200 OK
GET /api/records/:id Get a record by ID 200 OK
POST /api/records Create a record 201 Created
PUT /api/records/:id Update a record 200 OK
DELETE /api/records/:id Delete a record 204 No Content
```

Record fields
Field Type Notes
```
id Integer Generated automatically
title String Required
category String Required
description String Required
status String Required
created_at Timestamp Generated automatically by SQLite
```

Create and update requests send title, category, description, and status. The backend rejects missing, empty, whitespace-only, or non-string required values.

Example request body:
```
{
"title": "Example record",
"category": "Technology",
"description": "An example description.",
"status": "Active"
}
```

Shareable Modal URLs
Dialog Example
```
Create http://localhost:5173/?modal=create
Edit http://localhost:5173/?modal=edit&id=15
Delete http://localhost:5173/?modal=delete&id=15
```

For Edit and Delete, the specified ID must refer to an existing record. These URLs use localhost for local development; the frontend and backend are not deployed as part of these setup instructions.

Testing
Run the backend test suite:
```
cd server
npm test
```
The repository includes 14 backend tests covering record validation and REST API operations. API integration tests use a temporary SQLite database to keep test data separate from the application's records.

The frontend functionality can be checked manually by creating a record, editing it, deleting it after confirmation, trying the search/sort/pagination controls, and testing modal keyboard interaction and Back/Forward navigation.

Notes

- SQLite is stored locally in server/data/records.db by default. Database files are excluded from version control.
- The backend can use a different SQLite file path through the DB_PATH environment variable.
- The frontend currently calls the API at http://localhost:3001; if deployed, the API URL and cross-origin configuration need to be updated.
